# בולדיל — פלטפורמת דילים בזק לעסקים

מערכת מלאה לפרסום מבצעים מהירים: עסקים מפרסמים דיל לזמן קצוב (שעה עד 48 שעות), ה-AI מעצב לו כרטיס, והלקוחות בעיר רואים אותו מיד ומגיעים בחיוג או בניווט ב-Waze.

המערכת כוללת שלושה ממשקים:

| ממשק | כתובת | מה יש בו |
|---|---|---|
| **האתר הציבורי** | `/` | דילים חיים לפי עיר וקטגוריה, חיפוש ומיון, ספירה לאחור, עמוד דיל, עמוד עסק, חבילות, הרשמה וכניסה |
| **ממשק העסקים** | `/dashboard` | סקירה, מסך העלאת דיל עם תצוגה חיה, עיצוב AI, הדילים שלי, שאלת "האם הפרסום עזר?", סטטיסטיקות, חבילות ותשלומים, פרופיל, התראות, חלון צף ליצירת קשר |
| **אדמין העל** | `/admin` | דשבורד, עסקים (כולל פתיחת עסק עם 30 ימי ניסיון), דילים, סטודיו חבילות בסגנון קנבס, קטגוריות וערים, אנליטיקס כניסות עם ייצוא CSV/Excel, מודלי AI, תשלומים וטוקנים, פניות, שידור התראות, הגדרות, מנהלים ויומן פעולות |

## הפעלה מהירה

```bash
cd buldeal
cp .env.example .env      # ולעדכן JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm install
npm run dev               # שרת API על 3101 + Vite על http://localhost:5173
```

פרודקשן:

```bash
npm run build             # בדיקת TypeScript + בניית הצד הלקוח ל-dist/
npm start                 # השרת מגיש גם את ה-API וגם את האתר על PORT (ברירת מחדל 3101)
```

דרישות: Node.js 20 ומעלה. מסד הנתונים הוא SQLite (`data/buldeal.db`) ונוצר אוטומטית בהפעלה הראשונה, יחד עם קטגוריות, ערים, חבילות ומשתמש מנהל על.

### משתמשים לבדיקה

| תפקיד | אימייל | סיסמה |
|---|---|---|
| מנהל על | `admin@buldeal.co.il` (או `ADMIN_EMAIL`) | `Admin123!` (או `ADMIN_PASSWORD`) — **להחליף מיד** |
| עסק פעיל (הדגמה) | `demo1@buldeal.co.il` | `Demo1234` |
| עסק בתקופת ניסיון (הדגמה) | `demo5@buldeal.co.il` | `Demo1234` |

נתוני ההדגמה נטענים רק כאשר `SEED_DEMO=1` והמסד ריק. מכיוון שדילים נמחקים אחרי 48 שעות לכל היותר, אפשר לרענן את דילי ההדגמה עם `npm run seed:demo`. בפרודקשן מגדירים `SEED_DEMO=0`.

## חוקי המערכת

- **טוקנים:** כל פרסום של דיל עולה טוקן אחד. טוקנים מגיעים מהחבילה החודשית, מחבילות טוקנים או ממנהל.
- **משך דיל:** העסק בוחר בין שעה ל-48 שעות (ניתן להגדרה, אבל לא מעל 48). בסוף הזמן הדיל **נמחק אוטומטית** מהאתר, כולל התמונה שלו. נשאר רק סיכום (צפיות, לחיצות ותשובת "האם עזר") בהיסטוריה של העסק.
- **הרשמה דרך האתר:** חינם, בלי ח.פ ובלי כרטיס אשראי, עם **3 ימי ניסיון** וטוקן אחד בכל יום (הטוקן היומי לא נצבר). אחרי ההרשמה העסק **חייב לבחור חבילה** שתמשיך אחרי הניסיון.
- **עסק שנפתח על ידי האדמין:** מקבל **30 ימי ניסיון** כברירת מחדל. אפשר לשנות לכל עסק בנפרד, וגם את ברירת המחדל בהגדרות.
- **סוף הניסיון:** יום לפני הסיום נשלחת התראה (ובמייל, אם SMTP מוגדר). אם לא שולם, החשבון **נחסם מיד** והדילים יורדים. אחרי תשלום הוא נפתח שוב.
- **מנוי:** מתחדש אוטומטית עם הכרטיס השמור. אם החיוב נכשל יש תקופת חסד (ברירת מחדל 3 ימים) ואחריה חסימה.
- **אחרי כל פרסום:** בסיום הדיל העסק נשאל "האם הפרסום עזר והגיעו אנשים?" (כן/לא, ואופציונלית כמה לקוחות).

כל הערכים האלה ניתנים לשינוי במסך **הגדרות** באדמין.

## עיצוב כרטיס ב-AI

אחרי לחיצה על "פרסם", השרת שולח ל-Claude את פרטי הדיל, הקטגוריה והעיר, ומקבל מפרט עיצוב במבנה JSON: פריסה, פלטת צבעים, דוגמת רקע, גופן, כותרת, סטיקר, אימוג׳י ואנימציה. המפרט נבדק ומתוקן בשרת (כולל ניגודיות צבעים). הכרטיס עצמו תמיד מציג את הלוגו באמצע למעלה, את המחיר המקורי מחוק, את אחוז ההנחה, את המחיר הסופי ואת פרטי הקשר.

- ההגדרה נעשית בממשק **אדמין › מודלי AI**: בחירת מודל (ברירת המחדל היא Claude Opus 5.5), מפתח API, רמת מאמץ, יצירתיות והנחיית מערכת. יש גם בדיקת חיבור ומגרש ניסוי. אפשר במקום זאת להגדיר `ANTHROPIC_API_KEY` ב-`.env`.
- הבקשות משתמשות ב-Structured Outputs (JSON Schema), ובמודלים התומכים גם ב-fallback בצד השרת למקרה של סירוב.
- **בלי מפתח, או אם הקריאה נכשלת,** נכנס לפעולה מעצב מובנה לפי קטגוריה, כך שפרסום אף פעם לא נתקע. אפשר לכבות את ההתנהגות הזאת בהגדרות.
- כל קריאה נרשמת ביומן AI עם זמן תגובה, צריכת טוקנים ושגיאות.

## תשלומים

ספק הסליקה המובנה הוא **`demo`**: מצב הדגמה שמאשר כל כרטיס תקין ודוחה כרטיס שמסתיים ב-`0002`, כדי לבדוק כשל. **לא מתבצע חיוב אמיתי.**

לחיבור סליקה אמיתית (Tranzila, Cardcom, Meshulam, Pelecard וכו׳) מממשים ספק חדש ב-`server/services/billing.js` עם שתי מתודות: `tokenizeAndCharge` ו-`chargeToken`. אחר כך בוחרים אותו בהגדרות. בפרודקשן מומלץ להשתמש בשדות מאובטחים או בדף תשלום מתארח של הספק, כך שמספרי כרטיס לא יעברו בשרת.

## אפליקציה להתקנה (PWA)

אפשר להתקין את בולדיל כאפליקציה בטלפון או במחשב, בלי חנות אפליקציות:

- **אנדרואיד, כרום ו-Edge:** אחרי כמה שניות באתר מופיע באנר "בולדיל כאפליקציה בטלפון", ושם לוחצים על **התקנה**. כפתור "הורדת האפליקציה" נמצא גם בפוטר.
- **אייפון:** הבאנר פותח הוראות קצרות: בספארי לוחצים על **שיתוף**, ואז על **הוספה למסך הבית**.
- האפליקציה נפתחת במסך מלא, עם אייקון, מסך פתיחה בצבעי המותג וקיצורי דרך: "הדילים של עכשיו", "פרסום דיל חדש" ו"ממשק העסק".
- **עבודה בלי רשת:** הקוד של האתר הציבורי נשמר במכשיר מראש. רשימת הדילים והתמונות נשמרות מהטעינה האחרונה, ובזמן ניתוק מוצגת הודעה. נתונים פרטיים של עסקים ושל האדמין לא נשמרים לשימוש בלי רשת.
- **עדכונים:** בכל build נוצרת גרסה חדשה של ה-Service Worker (`public/sw.js`, שמקבל חותמת גרסה ב-`vite.config.ts`). מי שהתקין רואה הודעה "גרסה חדשה זמינה" ולוחץ **עדכון**.
- ה-Service Worker פעיל רק בבילד פרודקשן (`npm run build && npm start`), לא ב-`npm run dev`. התקנה דורשת HTTPS, חוץ מ-localhost.

## אנליטיקס

כל כניסה לאתר נרשמת עם מזהה מבקר אנונימי. לא נשמרות כתובות IP או פרטים אישיים. נרשמים גם צפיות בדילים, לחיצות על חיוג, Waze ושיתוף, חיפושים, סינון לפי עיר וקטגוריה, והרשמות. באדמין יש דוח לפי טווח תאריכים: גרף יומי, שעות, מכשירים, דפדפנים, מקורות הגעה, ערים וקטגוריות. הייצוא זמין ב-**CSV** או **Excel** (אירועים, סיכום יומי, דילים, עסקים, תשלומים).

## משימות מתוזמנות

השרת מריץ כל 30 שניות:
- העלאה לאוויר של דילים מתוזמנים, ומחיקה של דילים שהסתיימו
- תזכורת יום לפני סוף הניסיון, וחסימה בסופו אם לא שולם
- חידוש מנויים, תקופת חסד וחסימה
- טוקן יומי לעסקים בניסיון
- ניקוי אנליטיקס ישן לפי הגדרת השמירה

אפשר להריץ ידנית מהאדמין דרך **הגדרות › מערכת**.


## אבטחה

- סשן ב-cookie מסוג httpOnly (JWT). סיסמה חדשה מבטלת את כל הסשנים הקיימים.
- הגנת CSRF באמצעות כותרת חובה על כל בקשה שמשנה נתונים, ו-SameSite=Lax.
- הגבלת קצב על התחברות, הרשמה, יצירת קשר ואנליטיקס.
- העלאת קבצים: תמונות PNG, JPG, WEBP או GIF בלבד, עד 4MB, עם שם קובץ אקראי.
- מפתחות API וסיסמת SMTP מוצגים מוסתרים בממשק.
- CSP מגביל סקריפטים לאותו מקור.
